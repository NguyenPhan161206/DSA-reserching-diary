> Record of *how* I practised, not what I solved. The goal is to find repeat mistakes before they become
> exam/career habits. Template: `../NOTE_TEMPLATE.md` → TEMPLATE DSA-2.

**Target:** 5–8 problems per week across 2 sessions, at least 2 solved **without hints**.

---

## 🎯 Session Rules

| Rule | Why |
|------|-----|
| 60–90 minutes, fixed | Burnout produces notes, not skill |
| Read the problem, restate it, **write the constraints down** | Most wrong answers start here |
| Brute force first, then time it | Turns "feels slow" into a measured fact |
| No editor hints until 30 minutes in | The struggle *is* the learning |
| Log the session the same day | Memory of a session is unreliable after a day |

> Categories from `AGENTS.md` Section D. When one appears **three times**, it becomes a study task in the diary roadmap.

|------|---------|----------|---------------|------------------------|

**Recurring categories:**
- `misread constraint` — picked an algorithm that cannot meet the bound
- `wrong data structure` — had the right idea, no right container
- `off-by-one` — index/empty/single-element edge case
- `proof gap` — code worked, correctness argument missing
- `slow I/O` — right algorithm, TLE because of input handling
- `panic under time` — knew it, could not produce it
- `knew it, could not derive` — memorised pattern, no derivation
